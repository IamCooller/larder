# What worked

Every lever below is in the engine today, or was in it and was later replaced. Each row says what the lever does, whether it helps only mixture-of-experts (MoE) models or dense models too, the measured gain with machine, setup and date, the quality check it passed, and its status now. The ideas that were tried and closed are in [CLOSED.md](CLOSED.md); the machines, drives and models are in [HARDWARE.md](HARDWARE.md); how to read a row is in [README.md](README.md).

Names used in the tables:

- **M4**: the 16 GB M4 MacBook Pro. **PC**: the Linux PC, RTX 5060 Ti 16 GB, 15 GB RAM, one NVMe SSD.
- **35B mixed pack**: Qwen3.6-35B-A3B with 20 of its 40 layers' experts at 4-bit and 20 at 2-bit, 16.1 GB. Every 35B number measured on the M4 ran this pack, made by this engine's packer. The launcher installs the published 4-bit pack instead, which was measured only on the PC (2026-11-07).
- **Flash-Next**: Qwen3.8-Flash-Next. **EXL3 pack**: its 3-bit EXL3 experts, 45.8 GB. **4-bit pack**: its affine 4-bit experts, 75.5 GB. **K4**: its 4-bit EXL3 experts, 60.9 GB. **K8T**: K4's experts on an 8-bit trunk.
- **QSA**: Flash-Next's sparse attention; an indexer picks about 2,000 past keys for each new token, and attention reads only those.
- **ru / en / py**: the three standard prompts, Russian prose, English prose and Python code. A reply of 256 tokens unless a row says otherwise.
- **The Mac command**: `server.py --model <35B mixed pack> --prefill-step 0 --keep-convs 4 --mtp`, the 35B's recommended command on the M4.
- **The Flash-Next command (M4)**: `MOE_NATIVE=1 server.py --model <EXL3 pack> --mem-peak-gb 6 --mem-peak-max-gb 8 --cache-bias 0.5 --bias-budget 0.2`. Rows dated before 2026-10-21 ran it on the 4-bit pack.
- **The PC command**: `MOE_NATIVE=1 server.py --model <EXL3 pack> --mem-peak-gb 16 --cache-bias 0.5 --bias-budget 0.2` (15 GB before 2026-10-26).
- **Quality words**: "exact" means byte-identical replies at `--cache-bias 0` (or equal caches and logits); "ties only" means greedy-identical up to bf16 ties, each checked; "gate" means a paired GSM8K / HumanEval test whose McNemar test was not significant.
- **Status words**: "default" means on without a flag; "opt-in" means behind a flag or variable; "recommended" means in the recommended command but not a server default.

Numbers are measured unless marked "(est.)". Speedups are against the engine's own previous default unless a row names another baseline.

## The streaming design

These are the pieces the rest stands on. They were built and first measured before the period this record covers (by 2026-09-03), and none was re-measured alone on the M4 or the PC, so they carry no gain here. Their later effect shows up in every row below.

| lever | scope | measured gain | quality | status |
|---|---|---|---|---|
| **One record per expert.** `experts.bin` stores an expert's weights, scales and biases back to back, so one `preadv` scatters all three into place. | MoE only | built by 2026-09-03; not measured alone on these machines | exact by construction | default |
| **One read wave per layer.** The gate, up and down records of all chosen experts are issued together, so the SSD sees a deep queue instead of three shallow ones. | MoE only | built by 2026-09-03; not measured alone on these machines | exact by construction | default |
| **A resident arena addressed directly.** `gather_qmm`'s expert indices point at arena slots, so a hit costs nothing and a miss is read straight into its slot. | MoE only | built by 2026-09-03; not measured alone on these machines | exact by construction | default |
| **Zero copy.** An MLX array's buffer is a writable view into unified memory, so the read lands where the GPU reads it. | MoE only, Metal | built by 2026-09-03; not measured alone on these machines | exact by construction | default on Metal |
| **Next-layer guess.** Layer L+1's router applied to layer L's hidden state names most of the next layer's experts, so their reads start while the GPU still works on layer L. Routing is close to random across tokens but smooth across depth; the same mechanism is published as FATE (arXiv 2502.12224) and ExFlow (arXiv 2401.08383). | MoE only | built by 2026-09-03; its current forms are measured: staging rows (decode, [below](#decode-pipeline-and-kernels)), the prefill read-ahead ([below](#prefill-and-the-first-token)) and the CUDA staging reads ([below](#cuda-path)) | exact: a guess only decides what is read early | default |
